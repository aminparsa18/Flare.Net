# ADR-0216: Revert to hand-written MemoryPack TypeScript decoders

Status: Accepted

Date: 2026-10-13

Supersedes [ADR-0215](0215-patched-memorypack-typescript-generator.md); restores the arrangement
described in [ADR-0016](0016-memorypack-dashboard-typescript-adoption.md).

## Context

ADR-0215 (PR #682) replaced 141 hand-written decoders with ones generated by a patched
MemoryPack generator (`MemoryPack.Generator.DateTimeOffsetPatch`). ADR-0215 said the generated
`Map` -> `Record` conversion was "marginally cheaper" to avoid. Measured afterwards
(`src/dashboard/bench`, 10 interleaved runs per side, Node 26.5, byte-identical fixtures), the
log-search path is slower:

| 200-row `LogSearchResponse` page | Hand-written | Generated | Difference |
|---|---|---|---|
| Decode only | 534 ops/s | 514 ops/s | -3.8% (within noise) |
| Decode + the `api.ts` mapping | 442 ops/s | 394 ops/s | -10.8% (reproduced in both batches) |

An in-process A/B isolated the cause: the three attribute dictionaries decode into `Map`s and are
then copied into `Record`s by `mapToRecord`. Decoding them straight into `Record`s (what the
hand-written `string-record.ts` did) was about 18% faster than the generated path. Encode and the
JSON cases were unchanged.

## Decision

Revert PR #682. The dashboard goes back to the hand-written decoders under
`src/dashboard/src/lib/memorypack/`, and `Flare.Api` goes back to the stock `MemoryPack` package.
The patched generator and its fork are no longer referenced.

## Consequences

- Wire types are mirrored by hand again and must be kept in sync with the C# models field by field
  (the cost ADR-0215 removed).
- **Known regression risk:** the fork also fixed `readNullable*` treating a `null` whose padding
  bytes are non-zero as a value (seen in 2 of 500 round-tripped payloads). The hand-written decoders
  read nullable members through the stock runtime's `readNullableFloat64`/`Int32`/`Int64`/`Uint64`/
  `Boolean`/`Guid` and the whole-width `readNullableDateTimeOffset` helper (about 300 call sites),
  so that bug applies again. It existed before ADR-0215; a follow-up should route those reads through
  Flare-local helpers that inspect only the `HasValue` byte.
- The same trade can be revisited if MemoryPack's TypeScript generator gains `DateTimeOffset` and
  `IReadOnlyList`/`IReadOnlyDictionary` support upstream, ideally with a way to emit `Record` for
  `string -> string` dictionaries.
