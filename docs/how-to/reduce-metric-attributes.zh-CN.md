# 如何在摄取时精简指标的属性

当你无法修改记录指标的应用程序时,可以在 Flare 存储指标之前,去掉高基数的数据点属性,例如 `user.id` 或请求 ID。指标的序列数,以及随之而来的存储和查询成本都会下降,而无需改动发送端。

如果可以,最好在记录指标的地方修复该属性(参见[修复高基数指标](find-high-cardinality-metrics.zh-CN.md#修复高基数指标))。无法修改时再使用规则。

## 前提条件

- 成员(Member)或管理员(Admin)账号。查看者无法创建规则。
- 一个序列数很高的指标。[在指标目录中找到它](find-high-cardinality-metrics.zh-CN.md)。

## 创建规则

1. 打开**指标 > 目录**,点击该指标。
2. 在**在摄取时精简属性**中,勾选要移除的属性。每个属性旁显示其不同值的数量,高基数的那个一目了然。
3. 选择模式:
   - **丢弃所选**移除已勾选的属性,保留其余属性。
   - **仅保留所选**保留已勾选的属性,移除其余属性。
4. 点击**预览**。
5. 数字符合预期后,点击**创建规则**。

规则会在约 30 秒内对新数据生效。

## 保存前查看效果

**预览**会按存储的原样统计该指标最近一小时的活跃序列数,再统计去掉已勾选属性后的序列数。例如:"活跃序列数将从 19.9K 降至 1.2K。"对于前缀规则,还会列出每个匹配的指标,移除序列最多的排在前面。

预览基于已存储的数据统计,因此之前已被规则精简过的指标会显示为没有变化。预览是试运行:不会保存或更改任何内容。更改已勾选的属性或模式会清除预览。

## 规则的作用

- 仅作用于**数据点属性**。资源属性和作用域属性描述发送端,保持不变。
- 落在同一序列、同一时间戳的数据点会被合并。增量(delta)求和与增量直方图相加。Gauge 和累积型指标保留最后一个值。指数直方图的数据点会被精简,但不会合并。
- 同一指标上的多条规则按创建顺序依次应用,后一条看到的是前一条的结果。
- **被移除的属性无法恢复。**规则作用于存储时的数据。已存储的数据在过期之前仍保留其属性。
- 对**累积型**指标要谨慎。把多条累积序列合并为一条并保留最后一个值,并不等于它们的总和。建议对增量指标、Gauge 和直方图使用规则,或去掉本来在每个序列中就恒定不变的属性。

## 用前缀覆盖多个指标

目录只会为单个指标创建规则。要覆盖一族指标,例如 `http.client.*`,请通过 API 创建规则。名称可以在非空前缀之后以单个 `*` 结尾:

```bash
curl -X POST http://localhost:8080/api/metric-attribute-rules \
  -H "Authorization: Bearer $FLARE_PAT" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Drop user.id from HTTP client metrics",
    "metricName": "http.client.*",
    "mode": "Drop",
    "attributes": ["user.id"]
  }'
```

`POST /api/metric-attribute-rules/preview` 接受去掉 `name` 的相同请求体,并按匹配的指标返回序列数。前缀规则也会显示在它所匹配的每个指标的面板中,并标有"通过 http.client.*"。

规则名称唯一（不区分大小写）：保存与其他规则同名的规则会被拒绝并返回 409，因此工具可以按名称定位规则。

## 关闭或删除规则

指标面板会列出覆盖它的规则,包括前缀规则。用开关可以关闭规则而不删除它,用垃圾桶图标可以删除。变更刷新后,新数据会重新以完整属性存储。

## 找出不匹配任何指标的规则

指标被重命名、不再发送,或名称有拼写错误时,规则可能不再匹配任何指标。成员会在指标目录顶部看到一条警告,列出在最近 24 小时内未匹配任何已接收指标的规则,每条都有删除按钮。仅仅静默了一天的指标也会出现在这里,因此删除前请先核对名称。
