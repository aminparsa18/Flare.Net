# 查看存储的主要来源

在选择采样或[数据保留](set-data-retention.zh-CN.md)规则之前，可用**用量**页面查看哪些服务、摄取密钥和属性占用的存储最多。

## 打开页面

打开**设置 > 工作区 > 用量**（仅管理员），或访问 `/settings/usage`。可选择 1、7 或 30 天的时间范围。

## 显示内容

| 部分 | 含义 |
|---|---|
| 信号卡片 | 时间范围内各信号已存储的事件数，以及各信号当前的压缩磁盘大小 |
| 按服务统计 | 每个服务的事件数和每日事件数（每个信号前 50 名），以及估算的磁盘占用 |
| 摄取密钥 | 每个活动密钥在当前 UTC 日内被接受的事件数和字节数 |
| 最大的属性 | 按键加值字节数对最近样本行中的属性键排序 |

## 如何理解数字

- **估算磁盘占用**：将信号的压缩表大小按服务在时间范围内的事件占比分摊。ClickHouse 不记录每个服务的大小，因此仅用于排序，不适合计费。
- **摄取密钥**仅覆盖当前 UTC 日，因为 Redis 中每个密钥的计数器只保留这一窗口。
- **最大的属性**每个来源抽样最近一天最多 100,000 行，报告未压缩字节数。占比为同一来源内的比例。
- 经追踪采样的 span 按存储情况只计一次。

## 据此行动

在某个信号中占比过高的服务，可考虑更短的[数据保留](set-data-retention.zh-CN.md)规则或追踪采样。很少被查询的大属性可用[管道规则](manage-pipeline-rules.zh-CN.md)丢弃。
