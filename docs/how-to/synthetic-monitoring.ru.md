# Как следить за эндпоинтами, портами и сертификатами с помощью синтетических проб

Приложения сообщают о себе сами, и это не помогает, когда эндпоинт недоступен или сертификат скоро истечёт. **Синтетический монитор** — это проба, которую Flare запускает по расписанию снаружи. Результат хранится как обычные метрики, поэтому алерты и графики по нему строятся так же, как по любой другой метрике.

## Создание монитора

Откройте **Настройки > Workspace > Синтетические мониторы** и нажмите **Новый монитор** либо используйте API (`POST /api/synthetic-monitors`, роль Member или Admin) с cookie сессии или персональным токеном доступа:

```bash
curl -X POST "$FLARE_API/api/synthetic-monitors" \
  -H "Authorization: Bearer $FLARE_PAT" -H "Content-Type: application/json" \
  -d '{"name":"checkout health","kind":"Http","target":"https://shop.example.com/health","intervalSeconds":60}'
```

| Поле | Значение |
| --- | --- |
| `kind` | `Http`, `Tcp`, `Tls`, `Dns`, `Udp` или `Icmp`. |
| `target` | Http: абсолютный URL `http(s)`. Tcp: `host:port`. Tls: `host` или `host:port` (по умолчанию 443). Dns, Icmp: имя хоста или IP-адрес. Udp: `host:port`. |
| `method` | Только Http: `GET` (по умолчанию), `HEAD`, `POST` или `OPTIONS`. |
| `expectedStatus` | Только Http: статус, считающийся успешным. `0` (по умолчанию) — любой 2xx или 3xx. |
| `requestHeaders` | Только Http: заголовки запроса, по одному `Name: value` в строке. API никогда не возвращает значения: они читаются как `********`, а отправка `Name: ********` при обновлении сохраняет прежнее значение. |
| `requestBody` | Только Http, только `POST`: тело запроса. Тип задаёт заголовок `Content-Type`. |
| `expectedAnswer` | Dns: IP-адрес, который должен быть в ответе (`method` тогда — тип записи, по умолчанию `A`, либо `AAAA`). Udp: текст, который должен содержать ответ; `requestBody` — отправляемая датаграмма. |
| `bodyContains` / `bodyNotContains` | Только Http: тело ответа должно содержать / не должно содержать этот текст (с учётом регистра; читается только первый 1 МиБ). Невыполненное условие записывает `synthetic.up` = 0. |
| `bodyMatchesRegex` | Только Http: тело ответа должно соответствовать этому регулярному выражению. Движок работает за линейное время, поэтому lookaround и обратные ссылки отклоняются. |
| `jsonPath` / `jsonPathEquals` | Только Http: путь вида `$.data.items[0].status` или `$['key']`, который должен существовать в JSON-ответе и, при желании, равняться `jsonPathEquals` (строки без кавычек, остальные значения как JSON-текст). |
| `intervalSeconds` | От 10 до 86400, по умолчанию 60. |
| `timeoutSeconds` | От 1 до 120, по умолчанию 10, не больше интервала. |
| `enabled` | `false` ставит монитор на паузу. |

`GET`, `PUT` и `DELETE` для `/api/synthetic-monitors/{id}` читают, изменяют и удаляют монитор.

## Что записывается

Каждая проба пишет gauge-метрики для сервиса `flare-synthetic` с атрибутами `monitor` (имя), `kind` и `target`:

| Метрика | Значение |
| --- | --- |
| `synthetic.up` | 1, если проба прошла, иначе 0. |
| `synthetic.duration` | Время до ответа, соединения или рукопожатия, мс. |
| `synthetic.http.status_code` | Только Http: полученный статус. |
| `synthetic.cert.expiry_days` | Только Tls: дней до истечения сертификата. |

Тайм-аут, ошибка соединения, неудачное TLS-рукопожатие (его проваливает истёкший, недоверенный или не подходящий по имени сертификат) и неожиданный статус записывают `synthetic.up` со значением 0.

Таблица мониторов показывает последний результат каждого монитора (up или down и время пробы), а `flare synthetic-monitors list` показывает то же в терминале. Доступны также `create`, `update` и `delete`; см. [справочник CLI](../reference/cli-commands.ru.md).

## Проверки из нескольких локаций

Каждый `Flare.AlertWorker` называет место, откуда он выполняет проверки, через `Synthetic__Location` (по умолчанию `default`). Запустите по воркеру в каждом регионе со своим именем, все с одними и теми же ClickHouse и Redis, например `Synthetic__Location=eu-west` в одном и `us-east` в другом.

Поле **Локации проб** монитора (или `flare synthetic-monitors create ... --location eu-west --location us-east`) перечисляет локации, которые его выполняют; оставьте пустым, чтобы выполнять со всех воркеров. Каждая локация проверяет один раз за интервал, и каждый результат содержит атрибут `location`. Если сообщили несколько локаций, таблица показывает бейдж для каждой.

Алерт по `synthetic.up` с **Min** ниже 1 срабатывает, когда монитор недоступен хотя бы из одной локации. Чтобы срабатывать по кворуму локаций, используйте **Last**. Каждая локация это отдельная серия, а **Last** усредняет последний результат каждой серии, поэтому для `synthetic.up` это доля локаций, из которых монитор доступен:

| Срабатывать, когда | Агрегация и порог |
|--------------------|-------------------|
| недоступна любая локация | **Min** ниже 1 |
| недоступна как минимум половина локаций | **Last** ниже 0,51 |
| недоступны все локации | **Last** ниже 0,01 |

При четырёх локациях **Last** ниже 0,76 означает, что недоступны две или больше. Выбирайте порог между долями, которые нужно различать.

Вычислять это не обязательно: кнопка с колокольчиком в строке монитора открывает форму алерта с фильтром по этому монитору и выбором **Недоступен минимум из N из M локаций**, который сам задаёт **Last** и порог.

## Алерты по монитору

Создайте обычное правило алерта по метрике для одной из этих метрик с фильтром по атрибуту `monitor`:

- `synthetic.up` с **Min** меньше 1 за 3 минуты: эндпоинт был недоступен.
- `synthetic.duration` больше 2000 за 5 минут: он медленный.
- `synthetic.cert.expiry_days` меньше 14: пора обновить сертификат.
- **Отсутствие данных** по `synthetic.up`: сам монитор перестал отчитываться.

## Ограничения

- Пробы выполняются там, где работает `Flare.AlertWorker`; чтобы проверять из нескольких мест, см. [Проверки из нескольких локаций](#проверки-из-нескольких-локаций).
- Монитор заставляет сервер отправлять запросы на свою цель, включая внутренние хосты. Чтобы отключить пробы, задайте `Synthetic__Enabled=false` у воркера.
- `Synthetic__PollInterval` (5 с) и `Synthetic__MaxConcurrency` (20) настраивают исполнитель.
