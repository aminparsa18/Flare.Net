# Как отслеживать внешние API

Страница **External APIs** во Flare показывает все внешние хосты, которые
вызывают ваши сервисы: Stripe, Twilio, API соседней команды. Для каждого
домена видны частота запросов, доля ошибок и задержка, а в деталях -
показатели по эндпоинтам, коды ответа, самые частые ошибки и то, какие из
ваших сервисов делают эти вызовы.

Страница строится по client-span, которые ваши приложения уже отправляют.
Flare не нужен отдельный агент или изменения в приёме данных, и страница
работает и на span, сохранённых до того, как вы её открыли.

## Предварительные условия

- Работающий экземпляр Flare, принимающий трейсы от ваших приложений.
- Исходящие HTTP- или gRPC-вызовы, инструментированные OpenTelemetry.
  Это должны быть span типа `CLIENT` с атрибутом `server.address`
  (текущие семантические соглашения), `net.peer.name` (старые) или полным
  URL (`url.full` или `http.url`).

## Отправка client-span

Для `HttpClient` добавьте HTTP-инструментирование в трейсер:

```csharp
builder.Services.AddOpenTelemetry()
    .WithTracing(tracing => tracing
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation()
        .AddOtlpExporter());
```

Направьте экспортёр на OTLP-эндпоинт Flare, как обычно. Если проект
использует шаблон service defaults из .NET Aspire, инструментирование
`HttpClient` уже включено. gRPC-клиенты на основе `HttpClient`
(`Grpc.Net.Client`) покрываются тем же инструментированием.

## Страница External APIs

Откройте **External APIs** в верхней навигации. Каждая строка - один
домен:

| Столбец | Значение |
|---|---|
| Domain | `server.address`, иначе `net.peer.name`, иначе хост из URL. |
| Rate | Вызовов в секунду за окно. Наведите курсор, чтобы увидеть общее число. |
| Error rate | Доля вызовов со статусом span `Error`. |
| p95 / p99 | Перцентили длительности вызовов, измеренные на стороне вызывающего. |
| Endpoints | Число различных пар «метод + эндпоинт» на этом домене. |
| Last seen | Когда начался последний вызов в окне. |
| Services | Сколько ваших сервисов его вызывали. |

Список **Calling service** оставляет вызовы только одного сервиса, а
выбор окна позволяет задать от 5 минут до 24 часов. Страница загружается
по запросу; нажмите **Refresh**, чтобы обновить её.

Вызовы баз данных (задан `db.system`) и брокеров сообщений (задан
`messaging.system`) здесь не показываются, хотя и несут `server.address`.
Они видны на вкладке **Database calls** разбивки сервиса и на
[странице Messaging](monitor-message-queues.ru.md).

### Детали домена

Выберите домен, чтобы открыть подробности:

- **Status codes**: вызовы по HTTP-коду ответа
  (`http.response.status_code`, иначе `http.status_code`).
- **Endpoints**: частота, доля ошибок, p50/p95/p99 и время последнего
  вызова по методу и эндпоинту. Любой столбец можно отсортировать.
- **Top errors**: неудачные вызовы, сгруппированные по эндпоинту, коду
  ответа и `error.type`, с примером сообщения статуса. Строка без кода
  ответа означает, что ответ так и не пришёл - например, из-за тайм-аута
  или отказа в соединении.
- **Calling services**: какие ваши сервисы вызывают этот домен и как
  ведут себя их вызовы.

Нажмите на домен, эндпоинт, код ответа, долю ошибок, строку ошибки или
сервис, чтобы открыть **Traces** с фильтром по трейсам, содержащим
соответствующие вызовы. Это структурный запрос (**Structure A**), потому
что вызов - дочерний span в трейсе. См.
[Поиск трейсов по структуре](find-traces-by-structure.ru.md).

### Как называются эндпоинты

Flare называет эндпоинт по первому подходящему правилу:

1. Атрибут span `url.template` как есть. Его задают не все
   инструментирования.
2. Путь из `url.full` (или `http.url`), в котором каждый сегмент,
   похожий на идентификатор, заменён на `{id}`. Сегмент считается
   идентификатором, если он состоит только из цифр, является UUID или
   hex-строкой длиной от 16 символов, либо имеет длину от 16 символов и
   содержит цифру. Например, `/v1/customers/cus_NffrFeUfNV2Hib`
   превращается в `/v1/customers/{id}`. Строка запроса не учитывается.
3. `rpc.service/rpc.method` для gRPC.
4. Имя span.

Правило 2 эвристическое. Идентификатор, который ему не соответствует
(короткий slug, имя пользователя), остаётся в пути, и каждое значение
становится отдельным эндпоинтом. Если список получается шумным, задайте
`url.template` в инструментировании.

## Разбивка сервиса использует те же домены

В **Traces > Services > Map** щелчок по сервису открывает разбивку того,
что он вызывает. Вкладка **External calls** группирует по
`peer.service`, если span его задаёт, а иначе - по домену, определённому
так же, как выше. Раньше вызовы `HttpClient`, которые никогда не задают
`peer.service`, на этой вкладке не появлялись вовсе. В предагрегированных
данных разбивки по домену группируются только вызовы, сохранённые после
обновления; старые строки сохраняют группировку только по
`peer.service`, пока не устареют.

## Устранение неполадок

- **Страница пуста.** Проверьте, что вызовы порождают span типа
  `CLIENT`: откройте трейс в **Traces** и найдите дочерний span вида
  `Client` с атрибутом `server.address`. Если его нет, HTTP-
  инструментирование не зарегистрировано в трейсере, который отправляет
  данные во Flare.
- **Ссылка на трейсы домена ничего не находит.** Ссылка фильтрует по
  `server.address`. Span, которые называют хост только через
  `net.peer.name` или URL, учитываются на странице, но по ссылке не
  находятся.
- **В списке есть вызовы моих собственных сервисов.** Так и задумано:
  страница показывает все хосты, которые вызывают ваши сервисы, включая
  внутренние. Взаимодействие сервисов между собой показывает Service Map.
