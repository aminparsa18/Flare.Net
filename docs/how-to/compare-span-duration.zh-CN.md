# 如何判断一个 span 相对同类是否偏慢

一个耗时 800 ms 的 span，只有在同类 span 通常只需 50 ms 时才算问题。span 详情面板会把该 span 的耗时与同服务、同名称的其他 span 比较排名，帮助你区分“异常偏慢”和“本来就慢”的操作。

## 前提条件

- 一个正在运行、并接收应用追踪数据的 Flare 实例。
- 在被查看 span 前后一小时内，至少有 10 个同服务、同名称的 span。少于 10 个时 Flare 不显示排名，因为基于寥寥几个 span 计算的百分位没有意义。

## 查看排名

1. 打开 **Traces**，点击一条追踪将其打开。
2. 在瀑布图或火焰图中点击一个 span，详情面板会在右侧打开。
3. 在 span 名称和时间下方，找到类似 **`api` 中 `GET /orders` 的 p92** 的一行。

这一行表示参与比较的 span 中有 92% 不比它长。p95 或 p99 这样的高数值表示异常值；接近 p50 则表示该 span 耗时属于典型水平，即使这个耗时本身很长。

将鼠标悬停在这一行上可查看比较详情：参与比较的 span 数量，以及该组的 **p50**、**p95** 和 **p99** 耗时。

## Flare 与什么比较

- 与所选 span **服务名和 span 名称都相同**的 span。
- 仅包含在所选 span **前后一小时内**开始的 span。窗口是固定的，因此该数值在不同 span 之间含义一致。
- 所选 span 本身也计入该组。

HTTP 路由或状态等其他属性不参与匹配。如果同一个 span 名称下的请求成本差异很大，请使用 **Structure** 编辑器或属性筛选来缩小范围。

## 查看参与比较的 span

点击这一行。**Traces** 会打开，并带有针对该服务和 span 名称的[结构筛选](find-traces-by-structure.zh-CN.md)，按 **Duration** 从慢到快排序。时间范围是覆盖该 span 开始时间的最小预设，因此可能比排名所用的一小时窗口更宽。

## 通过 API 查询

面板调用 `POST /api/spans/duration-percentile`：

```json
{
  "serviceName": "api",
  "name": "GET /orders",
  "durationNano": 800000000,
  "startTime": "2026-10-03T09:15:00Z"
}
```

响应包含 `sampleCount`（无匹配时为 0）、`percentile`（0-100），以及 `p50Nano`、`p95Nano`、`p99Nano`。该端点不强制 10 个 span 的下限，是仪表板自行隐藏这一行；如果你依赖这个数值，请自行做同样的检查。
