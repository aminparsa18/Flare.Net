# Как найти трассировки по связям между их спанами

Структурный запрос показывает трассировки, спаны которых связаны так, как
вы описали. Например: «спан `checkout` вызывает `payment`, и этот спан
`payment` завершился ошибкой» или «трассировки, в которых `api` обращается к
базе данных, минуя кэш». Обычные фильтры проверяют спаны по одному и такое
выразить не могут.

Структурные запросы работают со спанами, которые Flare уже хранит, в том
числе с сохранёнными до того, как вы написали запрос.

## Предварительные требования

- Работающий экземпляр Flare, получающий трассировки от ваших приложений.
- Связываемые спаны должны входить в **одну трассировку** и быть связаны
  ссылками на родителя. Инструментации OpenTelemetry для HTTP, gRPC и
  систем обмена сообщениями по умолчанию передают контекст трассировки между
  сервисами.

## Задайте условия

1. Откройте **Трассировки** в верхнем меню и выберите диапазон времени.
2. Нажмите **Структура** на панели инструментов.
3. Каждая карточка с буквой (**A**, **B**, ...) — это условие для спана.
   Задайте любые из полей:
   - **Сервис**: точное значение `service.name` спана.
   - **Имя спана**: точное имя спана (операция).
   - **Статус**: Ошибка, OK или Не задан.
   - **Мин. мс**: спан длился не меньше указанного числа миллисекунд.
   - Фильтры **Атрибут** с теми же операторами, что и в обозревателе
     трассировок.

   Спан соответствует условию, когда выполняются все его настройки. Кнопка
   **Условие** добавляет карточку, всего до шести. Поля сервиса и имени
   спана подсказывают значения из выбранного диапазона времени.

## Напишите выражение

Объедините буквы в поле **Выражение**:

| Запись | Подходят трассировки, в которых |
|---|---|
| `A` | какой-то спан соответствует A |
| `A -> B` | спан, соответствующий B, — **прямой потомок** спана, соответствующего A |
| `A => B` | спан, соответствующий B, — **потомок** спана, соответствующего A, на любой глубине |
| `X AND Y`, `X && Y` | выполняются оба условия |
| `X OR Y`, `X \|\| Y` | выполняется хотя бы одно |
| `NOT X`, `!X` | X не выполняется |

Сильнее всего связывают `->` и `=>`, затем `NOT`, затем `AND`, затем `OR`.
Для группировки используйте скобки. Буквы и ключевые слова не зависят от
регистра.

Нажмите **Применить** или Enter. Список, счётчики фасетов и фильтр по
сервису теперь охватывают только подходящие трассировки. После закрытия
редактора выражение остаётся на кнопке **Структура**. Чтобы его убрать,
нажмите **Убрать** в редакторе или **Очистить фильтры**.

### Примеры

Если **A** — сервис `checkout`, а **B** — сервис `payment` со статусом
Ошибка:

- `A => B`: checkout привёл к неудачному платежу, напрямую или через другие
  сервисы.
- `A -> B`: checkout сам вызвал спан платежа, завершившийся ошибкой.
- `A => B AND NOT A -> B`: сбой произошёл глубже, а не в спане, который
  checkout вызвал напрямую.

Если **A** — сервис `api`, **B** — сервис `postgres`, **C** — сервис
`redis`:

- `A => B AND NOT A => C`: запросы, дошедшие до базы данных, не затронув
  кэш.

## Сохранение и публикация

Структура входит в состояние представления «Трассировки». **Представления**
→ **Сохранить текущее представление…** сохраняет её, ссылка на сохранённое
представление её восстанавливает, а **Закрепить на дашборде** превращает её
в панель.

## Использование из CLI

`flare traces` принимает те же условия в `--span` и выражение в `--where`:

```bash
flare traces --since 24h \
  --span "A:service=checkout" \
  --span "B:service=payment,status=error" \
  --where "A => B"
```

Значение `--span` — это буква, двоеточие и пары `ключ=значение` через
запятую. Ключи: `service`, `name`, `status` (`ok`, `error`, `unset`) и
`min-duration` (например, `500ms`). Условия по атрибутам доступны только в
дашборде. См. [`flare traces`](../reference/cli-commands.ru.md).

## Устранение неполадок

**«The expression uses condition D, which isn't defined.»** Для каждой буквы
в выражении нужна карточка. Карточки, не используемые в выражении,
игнорируются.

**«The expression also matches traces with none of its spans.»** Выражение
вроде `NOT A` само по себе совпало бы со всеми остальными трассировками
диапазона. Объедините его с условием, которое трассировка обязана
выполнять, например `B AND NOT A`.

**«Chains like 'A -> B -> C' aren't supported.»** Запишите каждую пару
отдельно: `A -> B AND B -> C`. Такая форма проверяет пары независимо,
поэтому B в каждой паре может быть разным спаном.

**Нет ожидаемой трассировки.** Учитываются только спаны, начавшиеся внутри
диапазона времени. Трассировка на границе диапазона может потерять спан,
связывающий два условия, — расширьте диапазон. Для `=>` нужны также все
промежуточные спаны. Если какой-то переход не был инструментирован или его
спан отброшен сэмплированием, цепочка на нём обрывается.

**Запрос выполняется медленно.** `=>` читает все спаны каждой трассировки,
которая может подойти. Сделайте условия точнее (сервис и имя спана, а не
только статус) или сократите диапазон.

Как вычисляются запросы и сколько они стоят, см.
[ADR-0069](../../docs-internal/adr/0069-structural-trace-queries.md).
