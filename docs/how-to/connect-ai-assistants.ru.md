# Как дать ИИ-ассистенту доступ к Flare

Запустите `flare mcp`, чтобы Claude Code, Cursor, VS Code и другие клиенты
[Model Context Protocol](https://modelcontextprotocol.io) получили доступ
**только для чтения** к вашим логам, трейсам, метрикам, исключениям и алертам.
Ассистент сам запускает `flare mcp` и общается с ним через stdin/stdout;
никакой новый порт не открывается. Так замыкается цикл отладки для
кодового агента: запустить приложение, воспроизвести баг, прочитать
телеметрию, изменить код, запустить снова и сравнить.

## Предварительные требования

- Установленный [CLI `flare`](run-with-cli.ru.md) (`dotnet tool install -g Flare.Cli`).
- Экземпляр Flare с данными: постоянный экземпляр от `flare start` или любой
  доступный Flare.Api (см.
  [Запрос к удалённому Flare](#запрос-к-удалённому-flare)).

## Подключение сервера к клиенту

**Claude Code**

```bash
claude mcp add flare -- flare mcp
```

**Cursor** — добавьте в `.cursor/mcp.json` (или `~/.cursor/mcp.json`):

```json
{ "mcpServers": { "flare": { "command": "flare", "args": ["mcp"] } } }
```

**VS Code** — добавьте в `.vscode/mcp.json`:

```json
{ "servers": { "flare": { "type": "stdio", "command": "flare", "args": ["mcp"] } } }
```

Именованный экземпляр выбирается так: `flare mcp -n <имя>` (см.
`flare instances list`). Без флага экземпляра используется тот же экземпляр,
что и в остальных командах `flare`.

## Инструменты

Все инструменты только читают и возвращают компактный текст с ограничением
объёма, чтобы нагруженная система не засыпала контекст ассистента.

| Инструмент | На какой вопрос отвечает |
|---|---|
| `search_logs` | События логов по сервису, уровню, тексту, id трейса, атрибутам. Не более 100 строк. |
| `search_traces` | Недавние трейсы (по строке на трейс), при желании только с ошибками или медленнее N мс. |
| `get_trace` | Один трейс в виде дерева спанов с отступами. Не более 200 спанов. |
| `list_metrics` | Какие метрики существуют (имя, тип, единица, сервис). |
| `query_metric` | Одна метрика по сериям: первое/последнее/мин/среднее/макс, а для гистограмм — перцентили. |
| `list_exceptions` | Топ групп исключений с количеством и затронутыми сервисами. |
| `list_firing_alerts` | Правила алертов, сработавшие прямо сейчас. |
| `list_runs` | Когда сервис запускался в последний раз и предыдущие запуски. |
| `diff_traces` | Сравнение двух трейсов: добавленные/удалённые спаны, изменения длительности и ошибок. |
| `compare_runs` | Один и тот же эндпоинт в предыдущем и в последнем запуске сервиса, с разницей. |

## Ограничение последним запуском

Во время разработки обычно важна телеметрия только что запущенного процесса, а
не последнего часа. Передайте `lastRun: true` (вместе с `services`) в
`search_logs`, `search_traces` или `list_exceptions`, и диапазон начнётся с
момента последнего запуска этого сервиса.

**Запуск** — это один старт процесса, определяемый по атрибуту ресурса
`service.instance.id`, который .NET Aspire и OpenTelemetry .NET SDK задают
новым значением при каждом старте. Реплики, стартовавшие с разницей менее
минуты, считаются одним запуском. Определение запусков читает спаны, поэтому у
сервиса, который отправляет логи, но не трейсы, запуск не определяется; для
таких используйте `since`.

## Сравнение до и после исправления

1. Вызовите эндпоинт (например, `POST /checkout`) и убедитесь, что он медленный
   или падает.
2. Пусть ассистент изменит код и перезапустит приложение.
3. Вызовите эндпоинт ещё раз.
4. Попросите `compare_runs` для этого сервиса и имени операции.

Сравнение сопоставляет спаны по сервису и имени и перечисляет добавленные или
удалённые спаны, изменения средней длительности не менее чем на 20 % и 5 мс, а
также изменения числа ошибок по спанам. `diff_traces` делает то же самое для
двух выбранных вами id трейсов.

## Запрос к удалённому Flare

```bash
flare mcp --api-url https://flare.example.com --token flr_pat_...
```

Если `--token` не задан, используется переменная окружения `FLARE_API_TOKEN`,
что позволяет не хранить токен в конфигурации клиента. Создайте токен, как
описано в
[Персональные токены доступа](configure-authentication.ru.md#персональные-токены-доступа);
он наследует вашу собственную роль, поэтому токен `Viewer` ничего не может
изменить, хотя инструменты и так только читают. В постоянном локальном
экземпляре аутентификация по умолчанию выключена, и он слушает только
loopback, поэтому токен не нужен.

## Ограничения

- Только stdio: у Flare.Api пока нет streamable-HTTP-эндпоинта.
- Инструментов записи (создание алертов, заглушение и т. п.) нет — так задумано.
