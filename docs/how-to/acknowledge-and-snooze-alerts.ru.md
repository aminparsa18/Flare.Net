# Как подтвердить или отложить сработавшее оповещение

Правило, которое остаётся в нарушении, отправляет уведомление снова после каждого
периода cooldown. Если кто-то уже занимается проблемой, эти повторы только шумят.
Подтверждение или откладывание говорит Flare, что их нужно прекратить.

## Подтверждение

На странице **Оповещения** у сработавшего правила в строке есть кнопка
подтверждения (двойная галочка). Откройте её, при желании добавьте заметку и
нажмите **Подтвердить**. В статусе правила будет указано, кто его подтвердил.

Подтверждение действует до конца инцидента:

- Пока правило остаётся в нарушении, новые уведомления о срабатывании не
  отправляются.
- Когда условие восстановится, уведомление о **восстановлении** всё равно
  отправляется, поэтому все, кого оповестили, узнают, что проблема решена.
- Если правило позже сработает снова как новый инцидент, прежнее подтверждение не
  действует.

## Откладывание

В том же окне выберите 15 минут, 1 час, 4 часа или 1 день, чтобы отключить
повторные уведомления до этого момента. В строке видно, когда откладывание
закончится. Если по окончании правило всё ещё в нарушении, оно снова отправит
уведомление при первой проверке после своего cooldown.

## Снятие

Пока правило подтверждено или отложено, та же кнопка превращается в **Снять
подтверждение**. После снятия следующее нарушение уведомит как обычно.

## Через CLI

```bash
flare alerts ack <rule-id> --note "Looking into the checkout DB"
flare alerts snooze <rule-id> --minutes 60
flare alerts unack <rule-id>
```

Идентификатор можно найти командой `flare alerts list`. Каждая команда завершается
с кодом 1, если правила нет или оно не сработало.

## Через API

Все три вызова требуют права на запись в проект правила и возвращают `409`, если
правило не сработало.

```bash
# Подтвердить, заметка необязательна
curl -X POST -H 'Content-Type: application/json' \
  -d '{"note":"Разбираюсь с БД оформления заказа"}' \
  http://localhost:5080/api/alerts/<rule-id>/ack

# Отложить на 60 минут (от 1 до 10080)
curl -X POST -H 'Content-Type: application/json' \
  -d '{"snoozeMinutes":60}' \
  http://localhost:5080/api/alerts/<rule-id>/snooze

# Снять
curl -X DELETE http://localhost:5080/api/alerts/<rule-id>/ack
```

`GET /api/alerts/states` содержит объект `ack` (кто, когда, тип, конец
откладывания, заметка) для каждого подтверждённого или отложенного правила. Если
аутентификация Flare выключена, поле «кто» пустое.

Почему всё устроено так: [ADR-0124](../../docs-internal/adr/0124-alert-acknowledgement-and-snooze.md).

## Эскалация, если никто не подтвердил

Правило может отправить неподтверждённый инцидент в дополнительные каналы. В
форме правила включите **Эскалировать, если не подтверждено**, задайте задержку
в минутах и выберите каналы. В API это `escalateAfterMinutes` (от 1 до 10080,
0 отключает) и `escalationChannelIds`.

Если инцидент уведомлён столько минут и не подтверждён, Flare один раз
отправляет его в каналы эскалации, добавив `[Escalated]` перед названием
правила, и записывает это в историю правила. Отложенные уведомления эскалацию
не останавливают, останавливает только подтверждение. Окно обслуживания её
откладывает. Сообщение «Resolved» по-прежнему уходит только в собственные
каналы правила.

Для эскалации нужны каналы из **Notification channels**, поэтому она недоступна
для правил со встроенным webhook или адресом e-mail.

Почему так: [ADR-0125](../../docs-internal/adr/0125-alert-escalation.md).

## Эскалация тому, кто на дежурстве

График дежурств — это список каналов уведомлений, которые сменяют друг друга,
каждый на смену фиксированной длины. Создайте его в **Настройки > Рабочее
пространство > Дежурства**: выберите каналы в порядке смен (по одному на
человека или команду), длительность смены в часах (сутки — 24, неделя — 168) и
время начала первой смены. С этого момента дежурит первый канал, через смену его
сменяет следующий, а после последнего список начинается заново. Страница
показывает, кто дежурит сейчас и до какого времени.

Затем в настройках эскалации правила выберите график. При эскалации Flare
отправляет инцидент в канал, дежурящий в этот момент, а также в фиксированные
каналы эскалации правила, если они есть. В API это `escalationRotationId` у
правила, а сами графики находятся в `/api/oncall-rotations` (`channelIds`,
`shiftHours`, `startsAt`).

График выбирает только получателя эскалации. Первое уведомление по-прежнему идёт
в собственные каналы правила. Если график удалить, его правила продолжат
эскалироваться только в свои фиксированные каналы. Разовых замен пока нет: чтобы
поменять смену, измените список участников.

Почему всё устроено так: [ADR-0126](../../docs-internal/adr/0126-alert-oncall-rotations.md).
