# Как отправлять телеметрию .NET-приложения во Flare

Отправляйте логи, трассы и метрики приложения ASP.NET Core или worker-сервиса во
Flare одним вызовом с помощью пакета `Flare.OpenTelemetry`. Это тонкая обёртка над
стандартным SDK OpenTelemetry для .NET: без агента и без собственного формата, а
любую другую настройку OpenTelemetry по-прежнему можно добавить рядом.

Если ваше приложение запускается внутри AppHost .NET Aspire, используйте вместо
этого [`Flare.Aspire`](../deploy/run-with-aspire.ru.md): он читает адрес, который
подставляет `.WithReference(flare)`. Эта страница — для всех остальных
.NET-приложений.

## Предварительные требования

- Запущенный экземпляр Flare ([автономный](../deploy/run-standalone.ru.md),
  [CLI](../deploy/run-with-cli.ru.md) или [Aspire](../deploy/run-with-aspire.ru.md)), чей
  OTLP-порт доступен из вашего приложения: `4317` для gRPC, `4318` для HTTP.
- Приложение на .NET 10.

## Добавьте пакет и вызов

```bash
dotnet add package Flare.OpenTelemetry
```

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.AddFlareTelemetry("http://localhost:4317");
```

Это вся настройка. Она регистрирует:

- OTLP-экспортёр для логов, трасс и метрик.
- Инструментирование ASP.NET Core и `HttpClient`: запросы и исходящие вызовы
  становятся спанами, а соответствующие метрики экспортируются.
- Метрики рантайма .NET: сборка мусора, пул потоков, исключения.

Логи, записанные через `ILogger`, несут идентификаторы трассы и спана
выполняемого запроса, поэтому во Flare можно переходить от строки лога к её
трассе и обратно.

## Настройка

У каждого параметра есть значение по умолчанию. Задавайте только нужное:

```csharp
builder.AddFlareTelemetry(o =>
{
    o.Endpoint = new Uri("https://flare.example.com:4318");
    o.Protocol = OtlpExportProtocol.HttpProtobuf;
    o.ApiKey = "<ключ приёма данных>";
    o.ServiceName = "orders";
    o.TraceSampleRatio = 0.1;
    o.ActivitySources.Add("MyApp.Orders");
    o.Meters.Add("MyApp.Orders");
});
```

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `Endpoint` | `http://localhost:4317` | OTLP-адрес Flare.Ingest. |
| `Protocol` | `Grpc` | `HttpProtobuf` для сетей, где gRPC заблокирован. Используйте HTTP-порт (`4318`); пути `/v1/traces`, `/v1/logs` и `/v1/metrics` добавляются автоматически. |
| `ApiKey` | нет | Отправляется как `Authorization: Bearer`. См. [ключи приёма данных](#использовать-ключ-приёма-данных). |
| `ServiceName`, `ServiceVersion` | существующий ресурс приложения | Атрибуты `service.name` и `service.version`. |
| `TraceSampleRatio` | `1` | Доля новых трасс, которую нужно сохранять, от 0 до 1. |
| `InstrumentAspNetCore`, `InstrumentHttpClient`, `InstrumentRuntime` | `true` | Отключает встроенное инструментирование. |
| `ActivitySources`, `Meters` | пусто | Имена ваших собственных `ActivitySource` и `Meter` для экспорта. |

Те же параметры привязываются из секции конфигурации `Flare`, поэтому при
развёртывании их можно задать переменными окружения, а код останется
`builder.AddFlareTelemetry()`:

```bash
Flare__Endpoint=http://flare:4317
Flare__ApiKey=<ключ приёма данных>
Flare__TraceSampleRatio=0.1
```

Значения, заданные в делегате, переопределяют секцию конфигурации.

## Семплирование трасс

`TraceSampleRatio` меньше `1` включает семплер по доле с учётом родителя. Сервис,
начавший трассу, решает, сохранять ли её, а каждый сервис, присоединившийся к
трассе, следует этому решению, поэтому в сохранённой трассе не пропадают спаны
нижестоящих сервисов. Чтобы это работало, используйте один и тот же помощник или
эквивалентный семплер с учётом родителя во всех сервисах на пути.

Это head-семплирование в приложении. Flare также может семплировать при приёме
данных; если хотите принимать решение централизованно, см.
[семплирование, кластеризация и стоимость](../../explanation/sampling-clustering-and-cost.ru.md).

## Использовать ключ приёма данных

Если ваш экземпляр Flare
[требует API-ключи приёма данных](../admin/configure-authentication.ru.md#ключи-api-приёма-данных),
передайте ключ вторым аргументом или задайте `Flare__ApiKey`:

```csharp
builder.AddFlareTelemetry("http://flare:4317", apiKey);
```

Не храните ключ в системе контроля версий: читайте его из конфигурации или
хранилища секретов.

## Использование вместе с другими экспортёрами

Помощник регистрирует экспортёры под собственными именами (`flare-logs`,
`flare-traces`, `flare-metrics`), поэтому он дополняет уже имеющийся в приложении
экспортёр, например отправляющий данные в другой бэкенд, а не заменяет его. Не
сочетайте его с `UseOtlpExporter()` для всех сигналов: SDK OpenTelemetry отказывается
запускаться, если зарегистрированы и он, и экспортёр для отдельного сигнала.

## Устранение неполадок

- **Ничего не приходит.** Проверьте, что порт соответствует протоколу (`4317` —
  gRPC, `4318` — HTTP) и что приложение до него дотягивается. Метрики по умолчанию
  экспортируются раз в 60 секунд, поэтому первые точки появляются до минуты.
- **Ничего не приходит, а прокси перед Flare пишет `301` или `308`.** OpenTelemetry
  .NET 1.20.1 и новее не следует HTTP-редиректам, поэтому прокси, который
  перенаправляет `http://` на `https://`, ломает каждый экспорт. Укажите в endpoint
  конечный адрес `https://` или настройте прокси так, чтобы порт OTLP обслуживался без
  редиректа.
- **`401` от Flare.** Экземпляр требует ключ приёма данных; см.
  [Использовать ключ приёма данных](#использовать-ключ-приёма-данных).
- **`ArgumentOutOfRangeException` при запуске.** `TraceSampleRatio` должен быть
  в диапазоне от 0 до 1.
- **У спана или лога показано «Отброшено атрибутов: N».** OpenTelemetry SDK приложения
  достиг лимита количества и отбросил N элементов перед отправкой, поэтому Flare не может
  их показать. Увеличьте соответствующий лимит в приложении:
  `OTEL_SPAN_ATTRIBUTE_COUNT_LIMIT`, `OTEL_SPAN_EVENT_COUNT_LIMIT`,
  `OTEL_SPAN_LINK_COUNT_LIMIT` или `OTEL_LOGRECORD_ATTRIBUTE_COUNT_LIMIT` (каждый по
  умолчанию берёт значение `OTEL_ATTRIBUTE_COUNT_LIMIT`, 128). Для этих счётчиков в
  существующем ClickHouse нужна [миграция 0091](../../../db/clickhouse/0091_dropped_counts.sql);
  строки, сохранённые раньше, ничего не показывают.
