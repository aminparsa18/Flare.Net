# Как найти N+1 запросы

N+1 запрос — это запрос к базе данных, который один и тот же участок кода выполняет снова и снова в рамках одного обращения, обычно по разу на каждую строку предыдущего результата. Flare находит их по спанам базы данных, которые уже хранит. Менять инструментирование не нужно.

## Как определяется шаблон

Flare группирует спаны базы данных одной трассы по родительскому спану и тексту запроса. Группа из **10 и более** одинаковых запросов под одним родителем считается N+1.

- Спан считается спаном базы данных, если у него есть `db.system.name` (или более старый `db.system`). Спаны базы данных без родителя игнорируются.
- Запрос — это текст запроса (`db.query.text` или `db.statement`), в котором строковые и числовые литералы заменены на `?`.
- Если у спана нет текста запроса, Flare использует операцию и таблицу, например `SELECT users`.

## Увидеть в одной трассе

1. Откройте трассу в разделе **Traces**.
2. На вкладке **Водопад** родительский спан с шаблоном N+1 отмечен меткой вида `N+1: 48× SELECT * FROM orders WHERE customer_id = ?`.

## Фильтр в списке трасс

Включите **Только N+1** на панели Traces, чтобы видеть только трассы с шаблоном N+1. Фильтр сочетается со всеми остальными и сохраняется в сохранённых представлениях.

## Найти самые проблемные запросы

1. Откройте **Traces**, затем вкладку **N+1**.
2. Выберите временное окно. При желании укажите имя сервиса или измените минимальное число повторов (по умолчанию 10, от 2 до 1000).
3. В таблице до 50 запросов, сначала самые затратные по суммарному времени. **Трассы** — сколько трасс показали шаблон. **Макс. повторов** — наибольшее число повторов под одним родителем.
4. Нажмите **Пример трассы**, чтобы открыть худший случай и увидеть метку.

Список считается по вашим спанам при открытии страницы, поэтому охватывает и данные, сохранённые до первого открытия. API — `POST /api/traces/n-plus-one`.
