# Как отправлять дашборд по почте по расписанию

Flare умеет по расписанию рендерить дашборд в PDF или PNG и отправлять его по почте, например еженедельный отчёт по SLO и задержкам для команды. У каждого расписания есть периодичность в формате cron, получатели, относительный период и, при необходимости, значения переменных. Каждая попытка записывается, а при сбое - с текстом ошибки.

Отчёты рендерит безголовый Chromium внутри `Flare.AlertWorker`: он открывает настоящий дашборд, поэтому отчёт выглядит так же, как дашборд. По умолчанию функция выключена, потому что воркеру нужны Chromium и SMTP-сервер.

## Включите отчёты

Понадобятся SMTP-сервер (значения `SMTP_*` в `.env` или настройки `Email__*` воркера, их же используют письма оповещений) и Chromium для воркера.

**Docker Compose.** Добавьте две строки в `.env`, затем пересоберите воркер, чтобы в его образ попал Chromium:

```bash
FLARE_REPORTS_CHROMIUM=true
FLARE_REPORTS_ENABLED=true
```

```bash
docker compose up -d --build alert-worker
```

**Любая другая установка.** Задайте воркеру:

| Параметр | Значение |
| --- | --- |
| `Reports__Enabled` | `true` - выполнять расписания. По умолчанию `false`. |
| `Reports__DashboardUrl` | URL дашборда так, как его видит браузер. Если не задан, берётся `Alerting__PublicUrl`. |
| `Reports__ApiUrl` | URL API так, как его видит дашборд, то же значение, что и `PUBLIC_API_URL` дашборда. |
| `Reports__ChromiumPath` | Исполняемый файл Chromium или Chrome. В образе Compose не нужен: в нём есть собственный Chromium от Playwright. |
| `Reports__BrowserWsEndpoint` | Сервер Playwright, к которому подключаться вместо запуска локального Chromium. |
| `Reports__PollInterval` | Как часто искать расписания, срок которых настал. По умолчанию 30 секунд. |
| `Reports__RenderTimeout` | Максимальная длительность одного рендера. По умолчанию 2 минуты. |
| `Reports__SettleDelay` | Дополнительное ожидание, чтобы графики дорисовались после того, как страница затихла. По умолчанию 3 секунды. |
| `Reports__MaxAttachmentBytes` | Максимальный размер отправляемого файла. По умолчанию 20 МБ. |

## Создайте расписание

1. Откройте дашборд и нажмите кнопку **Отчёты по расписанию** (значок календаря) на его панели.
2. Выберите **Новое расписание**.
3. Укажите название, периодичность (или пятипольное выражение cron, например `0 8 * * 1`), часовой пояс и получателей.
4. Выберите период и формат. **Взять текущий вид** копирует период и значения переменных, выбранные на экране.
5. Сохраните. В расписании будет указан следующий запуск.

Расписание выполняется с вашими правами: отчёт содержит то, что видите вы. Если вашу учётную запись отключить, расписание начнёт завершаться ошибкой. Создавать, изменять и удалять расписания могут роли Member и Admin.

## Проверьте и посмотрите историю

**Отправить сейчас** ставит расписание в очередь, и воркер отправляет отчёт примерно за минуту. **История запусков** показывает каждую попытку: статус, длительность, размер файла и текст ошибки при сбое. Типичные ошибки:

- *SMTP is not configured*: задайте `Email__Host` и `Email__From` у воркера.
- *No Chromium to render with*: соберите образ воркера с Chromium или задайте `Reports__ChromiumPath`.
- *Rendering took longer than ...*: увеличьте `Reports__RenderTimeout` или сократите период.
- *The rendered report is ... MB*: возьмите более короткий период или меньше панелей, либо увеличьте `Reports__MaxAttachmentBytes`, если это позволяет почтовый сервер.

## Ограничения

- Отчёт - это одна длинная страница высотой не более 16 000 пикселей. Более длинный дашборд обрезается.
- Отчёт - снимок дашборда на данный момент, а не выгрузка данных. Если в файле панель всё ещё показывает индикатор загрузки, увеличьте `Reports__SettleDelay`.
- Рендер, потерянный из-за перезапуска воркера, не повторяется. Следующий запуск по cron проходит как обычно.
- Единственный способ доставки - почта.
