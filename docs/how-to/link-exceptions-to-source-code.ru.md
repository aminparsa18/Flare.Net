# Как связать трассировки стека исключений с исходным кодом

На странице **Exceptions** откройте группу, чтобы увидеть примеры её
вхождений. Когда для сервиса настроен репозиторий исходников, путь к файлу в
каждом кадре стека становится ссылкой на этот файл и строку в вашем
репозитории на коммите, из которого собран сервис.

## Предварительные требования

- Трассировки стека с путями к файлам. .NET выводит `in /src/File.cs:line 42`,
  если сборка содержит portable PDB (так по умолчанию).
- Вы администратор или аутентификация отключена. Наблюдатели и участники видят
  ссылки, но не могут менять настройки.

## Пометьте сборку коммитом

Flare берёт коммит из атрибутов ресурса спана в таком порядке:

1. `vcs.ref.head.revision`
2. `vcs.revision`
3. `service.version`

Для .NET проще всего SourceLink: он добавляет коммит в информационную версию
(`1.2.3+abc1234`), и Flare читает часть после `+`. Если `service.version` —
просто `1.2.3`, коммит из неё не определить, и Flare использует ветку или тег
по умолчанию, указанные ниже.

## Настройте репозиторий

1. В строке вхождения нажмите значок ссылки рядом с **Show stack trace**.
2. Выберите хостинг: GitHub, GitLab или Azure DevOps.
3. Укажите URL репозитория, например `https://github.com/acme/shop`. Для
   Azure DevOps — `https://dev.azure.com/org/project/_git/repo`.
4. При необходимости задайте запасную ветку или тег, например `main`.
5. Задайте **префикс пути**, если путь сборки не относителен репозиторию. Это
   каталог, в котором шла сборка; Flare отбрасывает его из каждого кадра.
   Например, `/src/` при сборке в Docker или `/home/runner/work/shop/shop/` в
   GitHub Actions.
6. Нажмите **Save**.

Сборки с `<Deterministic>` и `ContinuousIntegrationBuild` уже переписывают пути
так, что они начинаются с `/_/`; Flare отбрасывает этот префикс без настройки.

## Показ строк кода прямо в интерфейсе

Если кадр ссылается на ваш репозиторий, под трассировкой стека появляется кнопка
**Show source**. Она показывает строки вокруг места выброса исключения (первый
кадр, который удалось связать со ссылкой).

API Flare получает файл с вашего хостинга репозиториев, поэтому для приватного
репозитория нужен токен доступа только для чтения. Введите его в той же форме со
значком ссылки:

- GitHub: fine-grained токен с доступом на чтение к **Contents**.
- GitLab: токен с областью `read_repository`.
- Azure DevOps: персональный токен доступа с правом **Code (Read)**.

Токен только записывается: Flare больше его не показывает, а пустое поле сохраняет
сохранённый токен. Публичные репозитории работают без токена. Flare не следует
перенаправлениям, пропускает файлы больше 2 МБ и кэширует файл на 10 минут.

## Объяснение исключения с помощью ИИ (необязательно)

Flare может попросить языковую модель объяснить исключение. Функция выключена по
умолчанию и использует вашу модель: любой OpenAI-совместимый endpoint, в том числе
локальный Ollama. Задайте для `Flare.Api`:

```bash
Ai__Enabled=true
Ai__Endpoint=http://localhost:11434/v1   # базовый URL; Flare вызывает /chat/completions
Ai__Model=llama3.1
Ai__ApiKey=...                            # для локальных моделей не обязателен
```

После этого под каждым вхождением появится кнопка **Объяснить это исключение**. По клику
модели отправляются тип и сообщение исключения, стек вызовов и исходный код места
возникновения. Перед этим Flare скрывает токены, пароли, секреты строк подключения, адреса
электронной почты и IP-адреса, но поиск по шаблонам может что-то пропустить, поэтому для
чувствительного кода используйте локальную модель. Запрос ограничен `Ai__MaxInputChars`
(12000), ответ — `Ai__MaxOutputTokens` (800). Каждый запрос попадает в журнал аудита, а
очищенный запрос пишется в лог на уровне Debug.

## Фильтрация логов и трейсов обычным языком (необязательно)

С теми же настройками `Ai__*` на страницах Logs и Traces появляется поле **Спросить ИИ**. Введите, например,
«5xx в checkout за последний час, кроме health-проверок», и Flare сам задаст период, сервисы, уровень,
текстовый поиск и фильтры по атрибутам. В Traces можно также построить структурный запрос
(«трейсы checkout, где упал span payments»). Модель лишь предлагает фильтры в фиксированном словаре, а не SQL.
Flare проверяет предложение, отбрасывает недопустимое и показывает результат как обычные редактируемые
фильтры. Модели отправляются запрос и названия сервисов (с редактированием секретов); данные логов и трейсов — нет.
Если часть запроса выразить не удалось, под полем появится пояснение.

## Когда кадр не становится ссылкой

Flare оставляет кадр обычным текстом, а не гадает:

- путь абсолютный и не начинается с заданного префикса;
- вместо пути только имя файла без каталога, как в кадрах Java;
- у вхождения нет коммита, а у сервиса нет запасной ветки.
