# Как архивировать телеметрию в S3-совместимое хранилище

Flare может записывать завершённые часы логов, трейсов и метрик в бакет в формате Parquet или NDJSON со сжатием gzip - для долгого хранения или анализа в DuckDB, Athena, Spark и подобных инструментах. Данные остаются и во Flare; архив - это копия. Чтобы хранить старые данные на дешёвом носителе так, чтобы по ним можно было *делать запросы*, см. [Как задать срок хранения данных](set-data-retention.ru.md).

## Включите архив

Создайте бакет (например, в RustFS или MinIO), затем задайте эти значения для **Flare.AlertWorker**. В автономном compose-стеке положите их в `.env`:

```bash
FLARE_ARCHIVE_ENABLED=true
FLARE_ARCHIVE_ENDPOINT=http://rustfs:9000/flare-archive   # URL бакета в path-style
FLARE_ARCHIVE_ACCESS_KEY=...
FLARE_ARCHIVE_SECRET_KEY=...
```

Используйте бакет, отличный от бакета холодного хранилища.

| Параметр (`Archive__…`) | По умолчанию | Значение |
|---|---|---|
| `Enabled` | `false` | Главный выключатель. |
| `Endpoint`, `AccessKey`, `SecretKey` | обязательны | URL бакета и учётные данные. |
| `Prefix` | `flare` | Префикс ключей внутри бакета. |
| `Format` | `Parquet` | `Parquet` или `Ndjson` (gzip, один JSON-объект в строке). |
| `Signals__0…` | все | Любые из `Logs`, `Traces`, `Metrics`. |
| `StartFrom` | текущий час | Время приёма, с которого начать при первом запуске, чтобы выгрузить историю. |
| `Lag` | `00:10:00` | Через сколько после окончания часа он выгружается. |
| `PollInterval` | `00:05:00` | Как часто искать завершённые часы. |
| `MaxWindowsPerPoll` | `6` | Часов на таблицу за один проход при догоне. |

## Что записывается

Один объект на таблицу и час, расположенный так, чтобы движки запросов отсекали ненужные даты:

```
flare/logs/dt=2026-10-08/hh=14/logs-20261008T1400Z.parquet
flare/spans/dt=2026-10-08/hh=14/spans-20261008T1400Z.parquet
flare/metrics_gauge/dt=2026-10-08/hh=14/metrics_gauge-20261008T1400Z.parquet
```

Включены все колонки. Часы определяются временем, когда Flare *получил* данные (`IngestedAt`), поэтому запоздавшее или задним числом событие попадает в час своего прихода. Час без данных не создаёт объекта. Неудавшийся час повторяется на следующем проходе, а повторная запись часа перезаписывает объект, так что повтор никогда не дублирует данные.

Прочитать обратно можно, например, в DuckDB: `SELECT * FROM read_parquet('s3://flare-archive/flare/logs/*/*/*.parquet')`.

## Ограничения

- Данные, появившиеся до включения архива, не выгружаются, если не задан `StartFrom`, и только пока они ещё есть во Flare.
- Профили и конфигурационные таблицы Flare не архивируются.
- Учётные данные передаются в ClickHouse внутри команды выгрузки, поэтому попадают в его журнал запросов.

Устройство описано в [ADR-0156](../../docs-internal/adr/0156-telemetry-archive-s3.md).
