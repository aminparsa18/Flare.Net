# Как организовать команды с помощью проектов

По умолчанию каждый вошедший пользователь видит все сервисы, дашборды, алерты и ключи приёма. **Проект** задаёт границу для команды: именованный набор сервисов и людей, которым разрешено их видеть. Для проектов должна быть включена аутентификация (см. [Настройка аутентификации](configure-authentication.ru.md)).

## Создание проекта

1. Войдите как глобальный Admin и откройте **Settings > Projects**, затем **New project**.
2. Задайте название и перечислите сервисы проекта, по одному `service.name` на строку. Завершающая `*` означает префикс (`checkout-*`). Одиночная `*` отклоняется, чтобы проект не мог незаметно владеть всем.
3. Откройте **Members** и добавьте пользователей с ролью в проекте: **Admin**, **Member** или **Viewer**.

Пересекающиеся шаблоны в разных проектах допускаются; пользователь видит объединение своих проектов.

## Что ограничивает проект

Как только существует хотя бы один проект, пользователь без прав администратора видит только сервисы, разрешённые его проектами: в логах, трассах, метриках, ошибках, панелях дашбордов, SLO и live-tail. Сервис, не подходящий ни под один проект, виден только глобальным Admin. Пользователь без проектов не видит ничего. Глобальные Admin всегда видят всё. Сужение шаблонов проекта действует сразу.

Не ограничиваются: страницы инфраструктуры, не привязанные к сервису (Hosts, Kubernetes, состояние приёма), и метрики отставания на уровне брокера (lag Kafka, глубина очередей).

## Назначение дашбордов, алертов, SLO, представлений и ключей приёма

В формах создания дашбордов, правил алертов, SLO и сохранённых представлений есть выбор **Project**, как и в **New key** на **Settings > Ingest keys**. Объект с проектом виден только участникам проекта и глобальным Admin. Объект без проекта относится ко всему инстансу, как раньше. Чтобы позже перенести ключ приёма, нажмите кнопку с папкой в его строке.

Для изменения объекта проекта нужна роль в проекте Admin или Member. Роль в проекте может лишь сузить глобальную: глобальный Viewer не сможет редактировать, даже будучи Member проекта. Admin проекта может изменять любой дашборд проекта.

Управление ключами приёма остаётся только за глобальными Admin, потому что ключ может принимать данные под любым `service.name`.

## Переключение проекта

Когда вы состоите в проекте, в верхней панели появляется переключатель проектов. Выбор проекта фильтрует дашборды, алерты, SLO и сохранённые представления по нему (объекты всего инстанса остаются) и делает его проектом по умолчанию для новых объектов. Доступная для запросов телеметрия не меняется: она всегда определяется вашим членством.

Удаление проекта скрывает его объекты от всех, кроме глобальных Admin, пока кто-то из них не переназначит их.
