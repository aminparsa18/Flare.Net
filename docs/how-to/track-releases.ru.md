# Как отслеживать релизы и внесённые ими ошибки

Отметка релиза сообщает Flare, что версия сервиса выкачена, и сохраняет коммит и время деплоя. Страница **Releases** затем показывает для каждой версии группы исключений, впервые появившиеся именно в ней.

## Отметить релиз из конвейера

Вызовите API на шаге деплоя с персональным токеном доступа (**Settings > Access tokens**) пользователя с ролью Member или Admin:

```bash
curl -X PUT "$FLARE_URL/api/releases" \
  -H "Authorization: Bearer $FLARE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"service":"orders-api","version":"2.4.0","commit":"'"$GIT_SHA"'","url":"'"$RUN_URL"'"}'
```

| Поле | Значение |
| --- | --- |
| `service` | `service.name` сервиса. Обязательно |
| `version` | Точно то `service.version`, которое передаёт сервис. Обязательно |
| `commit`, `url`, `notes` | Необязательно. `url` должен быть http(s)-ссылкой на коммит, pull request или запуск конвейера |
| `deployedAt` | Когда релиз выкачен (ISO 8601). По умолчанию сейчас |

Повторная отметка той же пары «сервис и версия» обновляет отметку. На локальном стеке то же делает `flare releases mark orders-api 2.4.0 --commit $SHA`, результат показывает `flare releases list --service orders-api`, а `flare releases delete` удаляет отметку. Удаление отметки никогда не затрагивает телеметрию.

## Страница Releases

Откройте **Releases** в меню и выберите сервис. Каждая строка — отмеченная версия с временем деплоя, коммитом и колонкой **Новые ошибки**: числом групп исключений, самое раннее записанное появление которых пришлось на эту версию. Раскройте строку, чтобы увидеть эти группы, самые частые первыми; каждая ведёт на страницу Errors, отфильтрованную по сервису и версии.

Группа считается новой, если за 30 дней до деплоя её не было. Группа, молчавшая дольше и вернувшаяся, считается новой в версии, где она вернулась.

## Регрессии

Группа, которую вы пометили решённой на [странице Errors](triage-errors.ru.md), получает статус **Regressed**, когда повторяется в версии, где её раньше не видели. Это работает только по `service.version`, с отметками релизов или без них. Страница Releases отвечает на другой вопрос: какие ошибки добавила конкретная версия.

## Ограничения

- Считаются только события исключений в спанах, сгруппированные по точному типу и сообщению, как на странице Errors.
- Телеметрия без `service.version` не относится ни к одному релизу.
- Счётчики новых ошибок считаются по вашим спанам при загрузке страницы и только для выбранного сервиса.
