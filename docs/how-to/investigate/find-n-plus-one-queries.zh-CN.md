# 如何查找 N+1 查询

N+1 查询是指同一段代码在单个请求内反复执行的数据库语句，通常是对前一个结果的每一行各执行一次。Flare 根据已存储的数据库跨度发现它们，无需修改插桩。

## 如何识别模式

Flare 按父跨度和语句对同一追踪中的数据库跨度分组。同一父跨度下有 **10 条或更多**相同语句的分组即为 N+1 模式。

- 带有 `db.system.name`（或较旧的 `db.system`）的跨度视为数据库跨度。没有父跨度的数据库跨度会被忽略。
- 语句取自查询文本（`db.query.text` 或 `db.statement`），其中的字符串和数字字面量被替换为 `?`。
- 如果跨度没有查询文本，Flare 改用操作和表，例如 `SELECT users`。

## 在单个追踪中查看

1. 在 **Traces** 中打开一个追踪。
2. 在 **瀑布图** 标签页中，执行了 N+1 模式的父跨度会显示类似 `N+1: 48× SELECT * FROM orders WHERE customer_id = ?` 的标记。

## 筛选追踪列表

在 Traces 工具栏中开启 **仅 N+1**，即可只列出包含 N+1 模式的追踪。该筛选可与其他筛选组合，并会随保存的视图一并保存。

## 找出最严重的问题

1. 打开 **Traces**，再打开 **N+1** 标签页。
2. 选择时间窗口。可选择输入服务名称，或修改最少重复次数（默认 10，范围 2 到 1000）。
3. 表格最多列出 50 条语句，按总耗时从高到低排列。**追踪数** 表示出现该模式的追踪数量，**最大重复次数** 表示单个父跨度下的最高重复次数。
4. 点击 **示例追踪** 打开最严重的案例并找到标记。

该列表在打开页面时根据您的跨度计算，因此也涵盖首次打开页面之前已存储的数据。对应的 API 为 `POST /api/traces/n-plus-one`。
