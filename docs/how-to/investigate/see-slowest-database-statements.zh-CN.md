# 如何查看最慢的数据库语句

**Database** 标签页会对服务执行的数据库语句排序，让你看到哪些语句耗时最多、执行最频繁或失败最多。它由 Flare 已存储的数据库 span 生成，无需修改你的埋点。

## 语句如何分组

- span 带有 `db.system.name`（或较旧的 `db.system`）时即为数据库 span。
- 语句是查询文本（`db.query.text` 或 `db.statement`），其中的字符串和数字字面量会被替换为 `?`，因此 `WHERE id = 42` 与 `WHERE id = 7` 算作同一条语句。这与 N+1 标签页显示的文本相同。
- span 没有查询文本时，Flare 改用操作和表，例如 `GET sessions`。
- 每一行按服务、数据库系统和语句区分。两代属性（`db.system.name` 和 `db.system`）会归入同一行。
- 与 N+1 检测不同，没有父 span 的 span 也会计入。

## 阅读表格

1. 打开 **Traces**，再打开 **Database** 标签页。
2. 选择时间窗口。也可以输入服务名或数据库系统，例如 `postgresql`。
3. 选择排序方式：**总耗时最长**、**p95 最高**、**调用最多**或**错误最多**。表格最多列出 100 条语句。
4. **调用/分钟**是调用数除以窗口时长。**平均毫秒**和 **p95 毫秒**按单次执行计算。**总毫秒**是所有执行的总和。
5. 点击**示例追踪**，可在其追踪中打开该语句最慢的一次执行。

如果你的服务启用了追踪采样，调用数、错误数和总耗时会按每个 span 的采样权重换算，因此频率不会被低估。

## 该用哪个标签页

- **Database** 回答“整体上哪条语句耗时最多”。
- **N+1** 回答“哪条语句被一次请求重复执行很多次”。
- span 详情中的耗时对比回答“这次执行相对同类是否偏慢”。

列表在打开时根据你的 span 计算。对应的 API 是 `POST /api/traces/db-statements`。
