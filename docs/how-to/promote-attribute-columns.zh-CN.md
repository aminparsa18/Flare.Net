# 如何加速对常用日志属性的过滤

如果你经常按同一个属性过滤日志（例如 `http.route`、`tenant.id` 或
`k8s.namespace.name`），可以把这个键提升为独立的列。之后 Flare 只读取这一列及其
自带的跳数索引，而不是每一行的整个属性映射。按该键过滤的搜索、图表和告警规则都会
变快，结果不变。

## 前提条件

- **Admin** 账户（或已关闭身份验证）。其他角色可以查看已提升属性的列表，但不能修改。
- 准确的属性键以及它所在的属性集：**日志**（日志记录属性）、**资源**（例如
  `service.namespace`、`k8s.namespace.name`）或 **作用域**。

## 提升一个键

1. 打开 **Indexing**，滚动到 **提升的属性**。
2. 选择属性集（**日志**、**资源** 或 **作用域**），输入键，例如 `http.route`。
3. 保持 **回填已有数据** 为开启状态，除非你的 `logs` 表非常大且旧数据很快会过期。
   参见[回填](#回填)。
4. 点击 **提升**。

该键会连同列名出现在表格中，例如 `attr_log_http_route`。在你所用的 Flare.Api
实例上，按该键的过滤会立即使用新列。其他 Flare.Api 实例和告警 worker 会在 30 秒内
生效。

键可以包含字母、数字和 `. _ - : / @`，最长 200 个字符。最多可以提升 50 个键。

## 回填

开启 **回填已有数据** 后，ClickHouse 会在后台重写已有数据，让旧行也获得该列和跳数
索引。状态列在完成前显示 **回填中**，完成后显示 **已生效**。表很大时可能需要一段
时间，并会占用磁盘 I/O。

回填期间按该键过滤的结果是正确的；关闭回填时也一样，只是旧数据得不到加速。不回填
时，旧数据只会随着 ClickHouse 的后台合并逐步获得该列。

## 哪些过滤会加速

以下运算符改为读取该列，而不是查找属性映射：

- **等于**
- **不等于**、**在列表中** 和 **不在列表中**，前提是比较值中没有空值

**存在**、**不存在** 和正则表达式运算符仍然读取属性映射，因为该列无法区分缺失的键
和空值。

## 撤销提升

在该键所在行点击 **撤销** 并确认。Flare 会删除该列及其跳数索引，按该键的过滤会重新
读取属性映射。日志数据不会丢失：属性仍然保存在映射中。
