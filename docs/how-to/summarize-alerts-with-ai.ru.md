# Как получить сводку ИИ по сработавшему оповещению

Flare может попросить языковую модель написать короткую сводку инцидента при
каждом срабатывании оповещения: первая ошибка, сбойный сервис или спан и то, что
изменилось по сравнению с предыдущим окном. Функция выключена по умолчанию и
использует вашу модель: любой OpenAI-совместимый endpoint, включая локальный
Ollama.

Сводка никогда не задерживает оповещение. Обычное уведомление уходит первым;
сводка создаётся потом и, если всё прошло успешно, появляется в истории
оповещений и приходит вторым сообщением.

## Как включить

Задайте эти переменные **и** для `Flare.Api`, **и** для `Flare.AlertWorker`
(сервисы `api` и `alert-worker` в `docker-compose.yml`). Именно воркер вычисляет
правила и обращается к модели:

```bash
Ai__Enabled=true
Ai__IncidentSummaries=true
Ai__Endpoint=http://localhost:11434/v1   # базовый URL; Flare вызывает /chat/completions
Ai__Model=llama3.1
Ai__ApiKey=...                            # необязательно для локальных моделей
```

Одной `Ai__Enabled` достаточно только для [«Объяснить это исключение»](link-exceptions-to-source-code.ru.md);
для сводок по оповещениям нужна ещё и `Ai__IncidentSummaries`.

## Что отправляется

По каждому сработавшему оповещению Flare отправляет имя, описание и порог
правила, наблюдаемое значение и ту же величину за предыдущее окно, а также
небольшую выборку подтверждающих данных в зависимости от типа правила:

- основные шаблоны логов окна (правила по логам и метрикам);
- самые частые исключения (правила по исключениям);
- сбойные спаны одной репрезентативной трассы.

Сначала Flare вырезает токены, пароли, секреты строк подключения, адреса почты
и IP-адреса, но поиск по шаблонам может что-то пропустить, поэтому для
чувствительной телеметрии используйте локальную модель. Точный очищенный промпт
сохраняется вместе со сводкой в таблице `alert_event_summaries` и пишется в лог
на уровне Debug.

## Ограничения

- Промпт ограничен `Ai__MaxInputChars` (12000), ответ - `Ai__MaxOutputTokens`
  (800).
- Не более `Ai__IncidentSummariesPerHour` (20) сводок в час на все правила.
  Оповещения сверх лимита сохраняют обычное уведомление, но без сводки.
- Одновременно выполняются две сводки; остальные пропускаются, а не ставятся в
  очередь.
- Для событий восстановления и оповещений, подавленных окном обслуживания,
  сводка не создаётся. Для оповещения об отсутствии данных сводка строится только
  по правилу, так как данных нет.

## Где видна сводка

- **История оповещений** в дашборде показывает её под событием простым текстом.
- **Дополнительное сообщение** в вебхуки Slack, Telegram, Microsoft Teams, Discord
  и почтовые каналы с заголовком `AI summary: <имя правила>`. PagerDuty, Jira,
  incident.io, JSM Ops и обычные вебхуки его не получают: второе сообщение
  открыло бы второй инцидент или выглядело бы как повторное оповещение.

Нужна миграция `0048_alert_event_summaries.sql`. На новых установках она
применяется автоматически; на существующем экземпляре выполните её вручную через
`clickhouse-client`.
