# Как следить за cron-заданиями и задачами по расписанию с помощью check-in

Задание, которое упало, пишет ошибку, по которой можно настроить алерт. Задание, которое так и не запустилось, не пишет ничего: планировщик умер, CronJob удалён, хост был выключен в 02:00. Этот случай закрывает **монитор check-in**. Задание обращается к URL Flare при запуске и при завершении, а Flare поднимает алерт, если обращение опоздало или сообщает об ошибке.

## Создание монитора

Откройте **Настройки > Workspace > Cron and job check-ins** и нажмите **New check-in monitor** либо воспользуйтесь API (`POST /api/checkin-monitors`, роль Member или Admin) с cookie сессии или персональным токеном доступа:

```bash
curl -X POST "$FLARE_API/api/checkin-monitors" \
  -H "Authorization: Bearer $FLARE_PAT" -H "Content-Type: application/json" \
  -d '{"name":"Nightly backup","cronExpression":"0 2 * * *","timeZone":"Europe/Berlin","graceSeconds":600,"maxRuntimeSeconds":3600}'
```

| Поле | Значение |
| --- | --- |
| `name` | Обязательно. |
| `slug` | Имя в ping-адресе: строчные буквы, цифры, `-` и `_`, не более 64 символов. Если не указан, берётся из названия; после создания не меняется. |
| `cronExpression` | Cron-выражение из пяти полей (минута час день-месяца месяц день-недели) или макрос вроде `@daily`, читается в часовом поясе `timeZone`. Укажите это поле или `intervalSeconds`. |
| `timeZone` | Имя IANA, например `UTC` (по умолчанию) или `Europe/Berlin`. Используется только вместе с `cronExpression`. |
| `intervalSeconds` | Второй вид расписания: ping ожидается каждые N секунд, от 60 до 2678400. Отсчитывается от последнего ping. |
| `graceSeconds` | На сколько позже ожидаемого времени может прийти ping, чтобы задание не считалось опоздавшим. По умолчанию 300. |
| `maxRuntimeSeconds` | Необязательно. Запуск, который начался и не завершился за это время, считается неисправным. 0 (по умолчанию) — без ограничения. |
| `enabled` | `false` приостанавливает монитор. |

`GET`, `PUT` и `DELETE` для `/api/checkin-monitors/{id}` читают, изменяют и удаляют монитор. Список мониторов доступен всем вошедшим пользователям; создание, изменение и удаление требуют роли Member или Admin.

Из терминала `flare checkin-monitors create "Nightly backup" --cron "0 2 * * *" --timezone Europe/Berlin --grace 600 --max-runtime 3600` делает то же самое для локального Flare, а `list`, `update` и `delete` управляют остальным; `list` показывает состояние каждого монитора, его последний и ожидаемый следующий пинг. См. [справочник CLI](../../reference/cli-commands.ru.md).

## Отправка check-in из задания

Задание обращается к `Flare.Ingest` на HTTP-порт (по умолчанию 4318) с [ключом приёма](../admin/configure-authentication.ru.md) — тем же, что используют ваши экспортёры OpenTelemetry. Путь без суффикса означает успех; `/start` и `/fail` — два остальных:

```bash
FLARE="https://ingest.example.com"
AUTH="Authorization: Bearer $FLARE_INGEST_KEY"

curl -fsS -m 10 -H "$AUTH" "$FLARE/v1/checkins/nightly-backup/start"
./backup.sh && curl -fsS -m 10 -H "$AUTH" "$FLARE/v1/checkins/nightly-backup" \
           || curl -fsS -m 10 -H "$AUTH" --data "backup.sh exited $?" "$FLARE/v1/checkins/nightly-backup/fail"
```

| Путь | Значение |
| --- | --- |
| `/v1/checkins/{slug}` или `/v1/checkins/{slug}/ok` | Задание завершилось успешно. |
| `/v1/checkins/{slug}/start` | Задание запустилось. Необязательно; отправляйте, чтобы заметить задание, которое запустилось и зависло. |
| `/v1/checkins/{slug}/fail` | Задание завершилось с ошибкой. |

Работают и `GET`, и `POST`. Тело `POST` до 4 КиБ сохраняется как сообщение (первые 1000 символов). Точка входа отвечает `204`, `400` при неверном слаге или статусе, `401` при отсутствующем или неверном ключе приёма и `503`, если ping не удалось сохранить, поэтому `curl -f` завершается с ошибкой. Ping для слага без монитора принимается и игнорируется.

В таблице мониторов у каждой строки есть кнопка **Copy ping command**.

## Как определяется состояние

Следующий ping ожидается в первое запланированное время после последнего ping. Каждый монитор находится в одном из состояний:

| Состояние | Когда | `checkin.up` |
| --- | --- | --- |
| Waiting for first check-in | Ping ещё не было, и первый не просрочен. | 1 |
| On schedule | Последний запуск завершился, следующий не просрочен. | 1 |
| Running | Запуск начался и не завершён, в пределах `maxRuntimeSeconds`, если он задан. | 1 |
| Late | Следующий ping не пришёл в течение допуска. | 0 |
| Failed | Последний запуск сообщил `fail`. Состояние сохраняется, пока запуск не сообщит об успехе. | 0 |
| Running too long | Запуск начался и не завершился за `maxRuntimeSeconds`. | 0 |
| Paused | Монитор отключён. Метрика не пишется. | нет |

Сохранение монитора перезапускает его отсчёт: первый ping ожидается в ближайшее после этого момента время по расписанию, поэтому изменение или повторное включение монитора никогда не помечает его опоздавшим сразу. Задание, которое запустилось, но не завершилось, при незаданном `maxRuntimeSeconds` считается опоздавшим, когда проходят его следующее запланированное время и допуск.

## Алерт по монитору

Каждые 15 секунд `Flare.AlertWorker` записывает gauge `checkin.up` (сервис `flare-checkin`, атрибут `monitor` равен слагу). Алерт по нему — обычный алерт по метрике: **Last** меньше 1, с фильтром по `monitor`. Кнопка с колокольчиком в строке монитора открывает форму алерта с уже заполненными значениями, остаётся выбрать канал уведомлений.

Чтобы узнать, что сам монитор перестал сообщать данные (например, остановлен worker), добавьте к правилу **Absent data**.

## Ограничения

- Любой действительный ключ приёма может отправить ping для любого слага. Выдайте заданиям отдельный ключ, а не используйте браузерный.
- Допуск должен покрывать расхождение часов, а для расписания по интервалу — ещё и время выполнения задания, потому что интервал отсчитывается от последнего ping.
- Опоздавшее задание обнаруживается не позже чем через `CheckIn__PollInterval` (15 с) после окончания допуска, поэтому используйте окна алертов длиннее.
- Установите `CheckIn__Enabled=false` на worker, чтобы отключить оценку. Ping по-прежнему сохраняются.
- Ping хранятся один год.
