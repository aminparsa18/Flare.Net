# Как опубликовать страницу статуса

**Страница статуса** — это страница только для чтения с состоянием сервисов, которую может открыть любой, у кого есть ссылка, без учётной записи Flare. Она показывает текущее состояние каждого компонента и ежедневную доступность за последние 90 дней. Компонент — это [синтетический монитор](synthetic-monitoring.ru.md) или [SLO](define-slos.ru.md), и страница показывает только заданное вами имя.

## Создайте страницу

Откройте **Settings > Workspace > Status pages** (Admin) и выберите **New status page**:

1. Задайте **название** и **слаг в URL** (строчные буквы, цифры и дефисы). Страница доступна по адресу `/status/<слаг>` на дашборде.
2. Добавьте **компоненты**: выберите мониторы и SLO и измените публичное имя каждого. Цели мониторов и имена SLO никогда не показываются.
3. Включите **Published**. Страницы создаются неопубликованными, а неопубликованная страница отвечает 404.

То же можно сделать через API (`/api/status-pages`, Admin) с сессионным cookie или персональным токеном доступа:

```bash
curl -X POST "$FLARE_API/api/status-pages" \
  -H "Authorization: Bearer $FLARE_PAT" -H "Content-Type: application/json" \
  -d '{"slug":"status","title":"Acme status","enabled":true,
       "components":[{"name":"Website","kind":"Monitor","refId":"<monitor id>"},
                     {"name":"Checkout API","kind":"Slo","refId":"<slo id>"}]}'
```

`GET`, `PUT` и `DELETE` на `/api/status-pages/{id}` читают, меняют и удаляют страницу.

## Что видят посетители

| Состояние | Компонент-монитор | Компонент-SLO |
| --- | --- | --- |
| Operational | Все недавно отвечавшие локации видят его доступным. | Бюджет ошибок не израсходован. |
| Degraded | Часть локаций видит его недоступным. | Бюджет ошибок превышен. |
| Outage | Все локации видят его недоступным. | |
| No data | Отключён, ни разу не проверялся или нет результатов за три интервала. | Нет трафика в окне SLO. |

Баннер вверху показывает худшее состояние среди компонентов. У каждого компонента также есть полоса до 90 дней, по одному сегменту на день UTC: зелёный при 99,9% и выше, жёлтый при 95% и выше, красный ниже. День монитора — доля успешных проверок. День SLO — доля хороших событий, и SLO показывает не больше дней, чем его окно.

## Управление страницами из CLI или Terraform

Для обоих нужна роль Admin.

```bash
flare status-pages create acme-public --title 'Acme status' \
  --component 'API=slo:<slo-id>' --component 'Website=monitor:<monitor-id>' --enabled true
flare status-pages list
flare status-pages update <id> --enabled false
```

`update` меняет только переданные опции; `--component` заменяет все компоненты.

С провайдером Flare для Terraform / OpenTofu:

```hcl
resource "flare_status_page" "public" {
  slug    = "acme-public"
  title   = "Acme status"
  enabled = true
  components = [
    { name = "API", kind = "Slo", ref_id = flare_slo.api.id },
  ]
  subscriber_channel_ids = [flare_notification_channel.oncall.id]
}
```

## Публикация инцидентов

Вычисленное состояние показывает, что работает; инцидент объясняет почему, вашими словами. В **Settings > Status pages** откройте диалог **Incidents** страницы, сообщите об инциденте с заголовком, статусом (Investigating, Identified, Monitoring или Resolved) и сообщением, затем публикуйте обновления по мере развития. Обновление **Resolved** закрывает инцидент.

Открытые инциденты показываются над компонентами на публичной странице, решённые остаются на ней 14 дней. Инциденты не меняют вычисленное состояние и баннер. API: `/api/status-pages/{id}/incidents`; текст обновлений публичный, не включайте в него секреты. Отметьте компоненты, которых касается инцидент, и публичная страница назовёт их рядом с ним; поле `components` в API принимает их id монитора или SLO, а следующее обновление может изменить список. Это только пометка: вычисленное состояние компонента не меняется.

### Уведомление каналов

Страница может сообщать вашим каналам, когда инцидент открыт или обновлён. В редакторе страницы добавьте каналы в разделе **Уведомления об инцидентах** или передайте `--subscriber <id-канала>` (можно повторять) в `flare status-pages create` или `update`; поле API называется `subscriberChannelIds`. Каждое обновление уходит сообщением со страницей, статусом, заголовком инцидента, вашим текстом, затронутыми компонентами и ссылкой на публичную страницу. Подходят только каналы webhook (включая Slack), Telegram, email, Teams и Discord; сбой доставки пишется в журнал и не мешает опубликовать обновление. Для ссылки нужен `Alerting__PublicUrl`. Это ваши каналы, а не форма подписки для посетителей.

### Подписка посетителей по email

Если сервер умеет отправлять почту (`Email__Host`, `Email__From`) и знает свой публичный адрес (`Alerting__PublicUrl`), на публичной странице появляется форма **Получать обновления по email**. Посетитель вводит адрес, получает ссылку для подтверждения и после подтверждения получает письмо о каждом инциденте, открытом или обновлённом на этой странице. В каждом письме есть ссылка для отписки. Без этой настройки форма скрыта. Посетители также могут отметить интересующие их компоненты; тогда они получают только инциденты, затрагивающие один из них, и любые инциденты без указанных компонентов. Подтверждённый адрес нельзя изменить через публичную форму (иначе любой, кто знает адрес, мог бы сузить чужие уведомления); вместо этого на странице с несколькими компонентами в каждом письме об инциденте есть ссылка **Выберите, о каких компонентах вы хотите получать письма**, которая открывает страницу, где подписчик отмечает компоненты и сохраняет выбор.

Неподтверждённому адресу повторное письмо уходит не чаще чем раз в 10 минут, страница хранит до 2000 подписчиков, а запросы на подписку ограничены 30 в час на адрес отправителя (за обратным прокси это адрес прокси). Форма отвечает одинаково, подписан адрес уже или нет. Администраторы смотрят подписчиков страницы через `GET /api/status-pages/{id}/subscribers` и удаляют одного через `DELETE /api/status-pages/{id}/subscribers/{subscriberId}`.

### Брендирование страницы и собственный домен

У каждой страницы могут быть **логотип** (`logoUrl`, изображение по https), **акцентный цвет** (`accentColor`, `#rrggbb`), **ссылка на поддержку** (`supportUrl`, https или `mailto:`), которая показывается как «Связаться с поддержкой», и **собственный домен** (`domain`, например `status.example.com`). Задайте их в редакторе страницы или флагами `--logo-url`, `--accent-color`, `--support-url` и `--domain` у `flare status-pages create` и `update`; пустое значение очищает поле, а пропуск оставляет его как есть.

Flare не выпускает сертификаты и не управляет DNS. Направьте DNS и TLS хоста (ваш обратный прокси или балансировщик) на дашборд, затем укажите домен у страницы. Этот хост отдаёт только страницу: `/` перенаправляет на `/status/<slug>`, а всё остальное, включая остальной дашборд, возвращает 404. Не используйте хост самого дашборда как домен страницы. Каждый домен принадлежит одной странице. Если дашборд обращается к API по другому адресу, чем браузеры, задайте `API_INTERNAL_URL` у дашборда. Изменения могут появляться до минуты. Письма подписки по-прежнему ссылаются на `Alerting__PublicUrl`.

## Что важно знать

- Страница публична для всех, кто имеет доступ к экземпляру. Снимите публикацию или удалите страницу, чтобы ссылка перестала работать сразу.
- Результат кешируется на 30 секунд, поэтому изменение может появиться с такой задержкой. Страница сама обновляется раз в минуту.
- Переименование монитора начинает его историю заново, потому что результаты проверок хранятся под именем монитора.
- Компонент, чей монитор или SLO удалён, остаётся на странице как **No data**; уберите его в редакторе.
