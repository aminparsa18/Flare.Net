# Как превратить поиск по логам в метрику

Считайте логи, подходящие под фильтр, по мере их поступления и сохраняйте
результат как метрику. Графики и правила алертов по такой метрике читают
небольшой временной ряд вместо сканирования таблицы логов каждый раз, поэтому
«ошибки checkout в минуту» остаются дешёвыми даже на загруженном экземпляре.

Метриками из логов управляют в **Настройки > Метрики логов** или через API.

## Требования

- Учётная запись Member или Admin либо [персональный токен доступа](configure-authentication.ru.md#персональные-токены-доступа)
  такой записи. Viewer не может создавать метрики из логов.
- Адрес API Flare, в примерах `http://localhost:8080`.

## Создайте метрику в дашборде

В обозревателе логов задайте фильтр, который нужно считать, и нажмите **Создать
метрику**. Форма откроется с уже подставленным фильтром, включая фильтры по
атрибутам. Укажите название, имя метрики и при необходимости ключи группировки,
затем нажмите **Оценить число рядов**: Flare прочитает последний час сохранённых
логов и покажет, сколько рядов создадут эти ключи, а также самые крупные из
них. Если число велико, уберите ключ перед сохранением. Можно начать и с нуля
кнопкой **Новая метрика логов** в **Настройки > Метрики логов**: там же метрики
можно просматривать, приостанавливать, изменять и удалять.

Тот же расчёт доступен как `POST /api/log-metrics/preview` с телом
`{ "condition": {...}, "groupBy": [...] }`.

## Создайте метрику из логов

Этот пример считает логи ошибок (серьёзность 17 и выше) сервиса `checkout` с
разбивкой по атрибуту `http.route`:

```bash
curl -X POST http://localhost:8080/api/log-metrics \
  -H "Authorization: Bearer $FLARE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Checkout errors",
    "metricName": "logs.checkout.errors",
    "condition": { "services": ["checkout"], "severityNumbers": [17, 18, 19, 20, 21, 22, 23, 24] },
    "groupBy": ["http.route"]
  }'
```

- `metricName` — имя, по которому вы строите графики и настраиваете алерты.
  Начинайте его с `logs.`, чтобы оно не совпало с метрикой, которую записывает
  приложение. Имя должно начинаться с буквы и состоять только из букв, цифр,
  `_`, `.` и `-`.
- `condition` принимает те же поля, что и условие
  [правила конвейера](manage-pipeline-rules.ru.md): сервисы, номера
  серьёзности, текст сообщения и условия по атрибутам. Пустое условие считает
  все логи.
- `groupBy` необязателен, до пяти ключей атрибутов. Каждый становится
  атрибутом метрики. Ключ берётся из атрибутов самого лога, затем из его
  атрибутов ресурса.

Метрика начинает считать новые логи примерно через 30 секунд. Уже сохранённые
логи не учитываются.

## Используйте метрику

Откройте **Metrics > Catalog**: `logs.checkout.errors` указана в списке как
любая другая метрика, с числом серий. Стройте её график в обозревателе метрик
или на панели дашборда, либо создайте на ней алерт по метрике. Это дельта-сумма
с единицей `{log}`, поэтому её значение за окно равно числу подходящих логов в
этом окне.

Каждая точка также несёт `service.name` логов.

## Следите за кардинальностью

Каждая уникальная комбинация значений группировки — отдельная серия.
Группируйте по атрибутам с небольшим числом значений, например по маршруту или
коду статуса, а не по идентификатору пользователя или запроса.

В качестве страховки одна метрика выдаёт не более 1000 различных комбинаций за
один сброс. Когда их приходит больше, лишние учитываются под значением
`__overflow__`: итог остаётся верным, но детализация теряется. Если на графике
виден `__overflow__`, уберите ключ группировки, который его вызывает.

## Изменение и удаление метрики

```bash
curl http://localhost:8080/api/log-metrics -H "Authorization: Bearer $FLARE_TOKEN"
curl -X PUT http://localhost:8080/api/log-metrics/<id> ...   # same body as create
curl -X DELETE http://localhost:8080/api/log-metrics/<id> -H "Authorization: Bearer $FLARE_TOKEN"
```

Значение `"enabled": false` приостанавливает подсчёт, не удаляя определение.
Удаление или изменение метрики не затрагивает уже сохранённые точки: они
остаются, пока их не удалит срок хранения метрик.
