# 如何对比服务的两次部署

Flare 会对比服务的两个版本，让你在一个页面上回答“这次部署有没有搞坏什么？”。除了给服务设置版本之外，不需要额外的埋点。

## 设置版本

设置 `service.version` 资源属性。在 .NET 中使用 OpenTelemetry：

```csharp
builder.Services.AddOpenTelemetry()
    .ConfigureResource(resource => resource.AddService("orders-api", serviceVersion: "2.4.0"));
```

任何字符串都可以（语义化版本、构建号、提交哈希）。版本从 span 和日志中读取，因此新部署一发送遥测数据就会出现。

## 对比

1. 打开 **Traces**，进入 **Services** 标签页。
2. 打开某个服务（在 **Map** 视图中点击它的节点）。
3. **部署对比**部分位于运行时健康结果下方。默认对比最新版本与它之前首次出现的版本。用两个选择器可以选择其他组合。

对比会回溯 7 天。如果服务在这段时间内只发送过一个版本，或没有任何 `service.version`，该部分会给出说明。

| 部分 | 显示内容 |
| --- | --- |
| 端点 | 按名称列出 server 和 consumer span：每个版本下的调用数、错误率和 p95 延迟。错误率上升一个百分点以上，或 p95 上升四分之一且至少 20 毫秒，会标记为**变差**。只有一个版本处理过的端点标记为**新增**或**已消失** |
| 新增异常类型 | 在当前版本中出现、而基准版本中从未出现的异常类型 |
| 新增出站依赖 | 当前版本调用过、而基准版本从未调用过的外部主机和数据库系统 |
| 新增日志模式 | 在当前版本中出现、而基准版本中从未出现的 Drain 日志模式 |

端点、异常类型和**此版本的日志**链接会打开对应的浏览器页面，范围限定为该服务和版本，时间为当前版本出现的时间窗口。

## 限制

- “首次出现”是在 7 天回溯范围内计算的，因此如果基准版本在回溯开始前就已停止发送数据，所有内容都会显示为新增。
- 没有 `service.version` 的遥测数据不会参与对比。
- 结果在你打开该部分时根据数据实时计算。背后的 API 是 `POST /api/services/version-comparison`。
