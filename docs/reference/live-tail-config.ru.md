# Ключи конфигурации live-tail

Точные ключи конфигурации WebSocket-эндпоинтов live-tail (`GET /api/logs/tail`, статистика хоста, граф ресурсов); задаются для `Flare.Api`.

| Ключ | Переменная окружения | Тип | По умолчанию | Значение |
|---|---|---|---|---|
| `LiveTail:PollDelay` | `LiveTail__PollDelay` | timespan | `250ms` | Пауза между чтениями потока Redis, если новых записей нет. |
| `LiveTail:ReadBatchSize` | `LiveTail__ReadBatchSize` | int | `1000` | Максимум записей за одно чтение потока. |
| `LiveTail:SubscriberChannelCapacity` | `LiveTail__SubscriberChannelCapacity` | int | `500` | Буфер одного соединения. Клиент, который не успевает, теряет события сверх этого предела, а не замедляет остальных. |
| `LiveTail:MaxClientMessageBytes` | `LiveTail__MaxClientMessageBytes` | int | `65536` | Наибольшее сообщение от клиента (сумма по фрагментам). Более крупное закрывает сокет с кодом 1009. |
| `LiveTail:MaxConnectionsPerUser` | `LiveTail__MaxConnectionsPerUser` | int | `10` | Одновременных сокетов live-tail на пользователя. Анонимные вызывающие делят одну корзину. При превышении обновление соединения отклоняется с кодом 429. |
| `LiveTail:MaxConnections` | `LiveTail__MaxConnections` | int | `200` | Одновременных сокетов live-tail на всех пользователей. При превышении обновление соединения отклоняется с кодом 429. |
| `LiveTail:MaxSocketLifetime` | `LiveTail__MaxSocketLifetime` | timespan | `00:05:00` | Сколько сокет остаётся открытым, пока сервер не закроет его, после чего дашборд переподключается. Ноль или отрицательное значение отключает ограничение. См. [Время жизни сокета](#время-жизни-сокета). |
| `LiveTail:MaxFilterItems` | `LiveTail__MaxFilterItems` | int | `100` | Максимум элементов в одном фильтре: сервисы, уровни серьёзности, имена областей, фильтры атрибутов и JSON-тела и их значения `in`/`not-in` вместе. |
| `LiveTail:MaxFilterStringLength` | `LiveTail__MaxFilterStringLength` | int | `1024` | Максимальная длина любой строки в фильтре (текст поиска, значения, ключи, пути). |
| `LiveTail:MaxRegexPatterns` | `LiveTail__MaxRegexPatterns` | int | `10` | Максимум операторов `regex`/`not-regex` в одном фильтре. |
| `LiveTail:MaxRegexPatternLength` | `LiveTail__MaxRegexPatternLength` | int | `256` | Максимальная длина одного регулярного выражения. |
| `LiveTail:RegexMatchTimeout` | `LiveTail__RegexMatchTimeout` | timespan | `50ms` | Тайм-аут одного сопоставления. Превышение считается отсутствием совпадения. |

## Проверка Origin

Браузеры не применяют CORS к WebSocket, поэтому `Flare.Api` отклоняет с кодом 403 запрос на обновление соединения, если его заголовка `Origin` нет в `Cors:AllowedOrigins` (переменные `Cors__AllowedOrigins__0`, `__1`, ...). Запросы без заголовка `Origin`, например от CLI `flare`, разрешены. Если дашборд открыт с источника, которого нет в списке, live-tail не подключится.

## Время жизни сокета

Авторизация проверяется только при открытии сокета. `LiveTail__MaxSocketLifetime` закрывает каждый сокет live-tail, статистики хоста и графа ресурсов по истечении этого времени, и дашборд переподключается, поэтому отозванная сессия, отключённый пользователь, истёкший персональный токен доступа или удалённое членство в проекте перестают получать поток в пределах этого окна.

## Регулярные выражения

Регулярные выражения live-tail выполняются за линейное время (`RegexOptions.NonBacktracking`). Опережающие и ретроспективные проверки и обратные ссылки отклоняются при отправке фильтра, поэтому сохранённое представление, которое их использует, перестанет работать в live-tail и его нужно переписать. Запросы поиска и агрегации не затронуты.

Значения по умолчанию рассчитаны на один сокет live-tail на открытую вкладку дашборда плюс по одному сокету статистики хоста и графа ресурсов на странице Resources, поэтому 10 на пользователя хватает для пользователя с несколькими вкладками. Устаревший сокет закрытой вкладки освобождает слот, когда сервер замечает разрыв или по истечении `MaxSocketLifetime`. Увеличьте `MaxConnectionsPerUser`, если пользователи получают 429 при переподключении, и `MaxConnections`, если одновременных пользователей больше примерно 20. Лимиты фильтров заметно выше того, что создаёт дашборд; увеличивайте их только для скриптовых клиентов. Статистика хоста и граф ресурсов тоже применяют `MaxConnectionsPerUser`, `MaxConnections` и `MaxClientMessageBytes`, у каждого эндпоинта своя корзина, поэтому они не вытесняют live-tail. Их входящие кадры отбрасываются, поэтому важны только число сокетов и размер сообщения.
